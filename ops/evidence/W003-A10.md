## 时序说明（任务书要求的重点）

**读档发生在标题之前，这是刻意设计而非缺陷。**
`app.tscn` 中 GameSession 是 App 的子节点，子节点 `_ready` 先于父节点执行，
因此 boot 时 GameSession._ready 已执行 `_try_load_autosave()`：有 auto 档则
restore 进 store，无档则保持初始态。此后玩家在标题上做选择：

1. **标题期冻结**：app._ready 检测标题可见 → 把 GameSession / WorldHost /
   Hud 的 `process_mode` 置 DISABLED（原值记录在 `_locked_process_modes`，
   解锁按原值恢复——Hud 在 ui_hud.tscn 中是 PROCESS_MODE_ALWAYS，不能简单
   恢复成 INHERIT，否则暂停菜单语义被破坏）。冻结范围覆盖 tick（事件/遭遇/
   结局/位置检查点）、建造热键、玩家移动/采集输入、HUD 菜单快捷键；自动
   存档只在 patch 提交后触发，而整条请求链冻结，**存档不可能被标题期污染**。
   仅锁 GameSession 不够：玩家节点在 WorldHost 子树，键盘 `space`/方向键会
   从 `_unhandled_input`/`_physics_process` 泄漏进游戏（信号投递不受
   process_mode 门控），故 WorldHost 一并冻结。
2. **继续（game_start(false)）**：存档已在 boot 时 restore——解锁即进入游戏；
   随后请求 `bgm_explore`，标题 0.8s 淡出，`fade_out_finished` 接续既有
   `_begin_startup_fade()`（2s 启动屏文案淡出）。解锁先于淡出完成，游戏循环
   在标题淡出期间即已运行（对话/遭遇的 ModalLayer=50 高于标题层 30，视觉无
   冲突）。
3. **新游戏（game_start(true)）**：读档可能已在 boot 时发生（旧档已进内存
   状态、玩家节点已被 `_place_player_from_saved_snapshot` 挪位），故 fresh
   不做就地 reset——复用 W001-P06 重启语义：`GameState.reset_to_initial()` →
   `SaveService.delete_slot("auto"/"manual")`（三代候选全删）→ 置 app.gd 的
   `static var _fresh_boot_pending`（static 存活于脚本资源，不随
   `reload_current_scene` 丢失）→ 重载场景。重载后的新 App._ready 消费标志：
   隐藏标题、直接解锁、请求 `bgm_explore`、接续启动屏淡出；且删档后重载的
   读档必然失败 → 干净初始态 + PlayerSpawn 出生点（玩家节点错位问题随场景
   重建消失）。测试经注入 `fresh_boot_handler` 替身覆盖 fresh 路由，不真实
   重载 GUT 场景；`_enter_game_after_fresh_reload` 分支公开可测。

## 决策

1. **启动屏保留为标题背景层**（任务允许的两个选项中取改动力度最小者）：
   TitleScreen(layer 30) 不透明背景遮住 UILayer(20) 的启动屏与游戏画面；
   标题淡出后玩家恰好看一段既有启动屏文案再进游戏，两层文案形成
   "菜单 → 开场" 的叙事接续。
2. **标题场景自包含**：`scenes/title_screen.tscn` 应用 `starsoil_theme.tres`，
   Root mouse_filter=STOP 挡鼠标，说明面板默认隐藏、按钮切换。
3. **退出分层**：TitleScreen 只发 `quit_requested`（层内不得自杀退出，测试
   套件才能存活），app 层执行 `get_tree().quit()`。
4. **A9 接线不入侵 game_session**：任务允许"可加 audio 注入钩子参数"，但
   app 层守卫装配已覆盖需求（`ResourceLoader.exists` → `load()` → `.new()`
   → add_child；`_play_bgm` 对缺席/无方法/resolver 未注入三层静默跳过），
   game_session 保持零改动。A9 合入后无需再改任何文件即自动生效；
   `test_app_audio_guard_assembles_or_skips_by_a9_presence` 在 A9 缺席/在场
   两种未来下都成立。
5. **fresh 引导缺省实现放 app 层**而非调用 game_session 私有方法
   （`_on_restart_requested`）：语义等价（reset_to_initial + delete_slot
   auto/manual + reload），但不对集成层私有 API 产生耦合；scene_reloader
   注入点语义（测试防重载）由 app 的 `fresh_boot_handler` 注入点对等承担。

## 限制

1. 音频仅接线到 A9 注入点：A9 未合入前 `play_bgm` 无实际发声（守卫跳过）；
   BGM 轨道 id（`bgm_title`/`bgm_explore`）为约定名，A9 若定名不同需在
   app.gd 两个常量处对齐（一处改动）。
2. fresh 路径采用场景重载语义：点击"新游戏"到重载完成有一帧级切换，无
   淡出过渡（当前实例直接销毁重建）；标题淡出仅用于"继续"路径。
3. 标题期玩家按 Esc 会被 HUD 吞掉吗——不会：Hud 已冻结；但 ModalLayer 的
   DialogueBox 仍为 INHERIT（初始隐藏且事件链冻结，无实际影响）。
4. `has_save` 缺省探测用 `SaveService.load_slot("auto")` 全量读档判定可用性
   （每次 boot 至多一次，垂直切片体量下开销可忽略）。
5. 测试按鸭子类型经 `get_node("%...")`/`set()`/`call()` 访问 TitleScreen
   （运行时 load），未用全局类名——避免 W002-GAP4 式 Parse Error 级联；
   代价是失去静态类型检查（app.gd 内部以强类型 `TitleScreen` 引用）。
