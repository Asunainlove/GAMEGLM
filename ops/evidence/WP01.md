## Decisions and limitations

- No `class_name` on the autoload script (parse conflict, see above); interface otherwise matches contract §3 verbatim.
- Content files may hold a single definition object or an array of definitions (same shapes ContentDB accepts); the Python validator mirrors this and additionally rejects duplicate ids per file, matching ContentDB `duplicate_id` semantics.
- `validate_refs()` covers the spec-required refs (building inputs + embedded recipe items, event `grant_items`, encounter `unit_id`s, unit/phase `action_ids`, building `effect_flag` as snake_case-only) and additionally checks unit drops, action costs, event `due_encounter`, and encounter `item_ids`/`intro_event_id`.
- Canonical JSON for `content_hash()` is implemented independently inside `src/content/content_db.gd` (sorted keys, compact separators, integral floats normalized, full float precision); SaveCodec is not reused.
- Validator policy: missing/empty `data/` → explanation + exit 0; a partial pack (some targets present, others missing) is a listed failure, since §6 defines the complete WP12 layout.
- `validate_content.py --data-root/--schemas-dir` exist for offline self-testing; defaults resolve to `<repo>/data` and `<repo>/schemas` with no arguments.
- Installed jsonschema is 4.25.0 vs the `requirements-dev.txt` pin 4.25.1; both are draft 2020-12 API-compatible. No `pip install` was performed in this environment.
- Bootstrap does not yet feed `GameState.content_hash` wiring (WP04/G2 integration).
