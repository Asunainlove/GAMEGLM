## 初始现状（审核基线上的实测）

- `event_approach.json` / `event_station_mode.json` / `event_policy.json` 三处
  choice 共 5 条 relation_delta（approach +5 trust / station_mode_symbiosis
  +10 trust），effect 步骤无 relation_delta 通道 → 信任经济上限 15。
- `EventRunner.apply_effect_step` 只提交 flag/grant_items/due_encounter。
- `ContentDB._validate_step("effect")` 拒绝 `relation_delta` 未知字段。
- `DialogueBox.show_choice(step)` 无禁用态；`_on_option_pressed` 先
  `_clear_options()` 再 emit；`GameSession._on_option_chosen` 失败即 return。
- 审核过程额外发现两条**死链**（缺口报告未列出，均在本包修复）：
  1. `approach_direct/approach_diplomatic` 不写 `set_flag` →
     `Progression.due_event` 的 `requires_any_prefix: approach_` 永不满足 →
     `event_policy` 在正常流程不可达（单测手工塞 flag 掩盖了这一点）。

     只能靠 encounter_won 触发，而正常流程伏击胜利先于政策选择 →
     `encounter_leviathan_due` 永不置位 → leviathan/结局链死锁。

## 实现摘要

### 任务1（契约修订，协调者已授权）

- `schemas/event.schema.json`：effect 步骤新增可选 `relation_delta`
  （与 choice option 同形 `{char_id, dim, delta}`）。
- `content_db.gd`：抽出 `_validate_relation_delta` 供 choice/effect 共用
  （char_id 稳定 ID + dim ∈ affection/trust/ideology + delta ∈ [-100,100]）；
  effect step 的 `_reject_unknown_fields` 白名单加入 `relation_delta`。
  `validate_refs` 无需新增（relation_delta 无跨表引用）。
- `event_runner.gd`：`apply_effect_step` 沿 **choose_option 现有 deferred_ops
  通道**（最小侵入，保持 value 形状 `{"deferred_ops": [...]}` 兼容）：当前
  关系值从 store 快照派生（契约 §0，null → GameState autoload；无 snapshot
  方法的替身按空字典处理，缺失值 0），clamp 后作为 deferred op 返回；
  delta-only 步骤零 patch；直接 op（flag/items/due_encounter）与原语义一致。

### 任务2（信任经济）

- 5 个羁绊事件（原创中文台词 3 行/事件，effect 步骤带 relation_delta，无 choice）：
  `event_drift_aftermath`（requires encounter_first_drift_won）、
  `event_husk_aftermath`（requires encounter_husk_ambush_won）、

  `event_leviathan_aftermath`（requires encounter_leviathan_won）。
- `progression.gd`：`_event_chain` 插入 5 事件，done 判定沿用
  `event_%s_done` 模板，前置 flag 未满足即跳过。
- 顺序裁定：`workshop_guide → misa_campfire`（同前置按序触发）与
  `station_mode → echo_resonance`（同前）保证策略上
  「Sanctuary 在 policy 前达标、Symbiosis 在结局前达标」；
  `husk_aftermath` 置于 `station_mode` 前，使正常流程在回响舱激活前完成
  第三笔 +12。
- `event_approach.json`：两个选项补 `set_flag: approach_direct /
  approach_diplomatic`——契约 §7「三次选择：…选项 flag approach_direct /

## 决策与限制

1. **effect relation_delta 走 deferred_ops 通道**而非并入 EventRunner 直接
   patch：保持「WP08 只直接提交主已有 patch 操作、WP04 操作经集成层落账」的
   冻结契约注释与 DuckStore 形状，最小侵入。
2. **approach set_flag 属数据修订而非行为变更**：契约 §7 逐字列明这两个
   选项 flag；WP12 落数据时遗漏（test_content_data 注释自认「不写 flag」，
   该文件不在本包允许路径，未改动——其现有断言对新增 set_flag 仍全绿）。
3. **policy_chosen 接线属集成层最小修复**：`Progression.react` 分支是冻结
   契约 API 却无调用方；不接线则任务书的「走完 leviathan_aftermath」曲线
   验证在正常流程不可达。门控条件（双胜利 + policy flag）不变。
4. **曲线测试以胜利 flag 模拟遭遇**：Boss 战确定性自动对局为战败（既有
   `test_encounter_chain_defeat...` 佐证），战斗链可玩性由遭遇专项测试覆盖；
   曲线测试的断言对象是事件链与经济数值。
5. **symbiosis 需要信任最优路线（approach_direct）**：见曲线表备注，70 为
   恰好达标，无冗余；是否加冗余交协调者裁定。
6. 事件文件行数 3 行/事件，满足 `test_content_data` 的 2..4 行约束；
   文案全部原创中文，无既有角色/游戏用语。
7. `Verify-Slice` 在 worktree 生成 `build/starsoil/` 导出产物（gitignore 内，
   不入库）。
