## 目标

- `Gathering.mining_result(cell_def, tool_tier)`：确定性单次敲击结算（soil/负硬度 → `not_mineable`；工具等级不足 → `tool_too_weak` 且 hardness_left=hardness；否则 hardness-1，敲到 0 且 hardness>0 时结算产出并 `depleted: true`）。
- `Gathering.apply_mining(state, chunk_id, cell, cell_def, tool_tier, store=null)`：已破坏格失败 `cell_already_destroyed`；reason 非空按 reason 失败；未耗尽成功但不产生持久 patch；耗尽提交**单个** patch（`set_destructible_cell(..., true)` + `add_item`），source_id=`gathering_<chunk_id>_<x>_<y>`（稳定 snake_case），expected_revision 取 `state.revision`，commit 结果透传。
- `InventoryModel`：按 item_id 排序的堆叠清单、容量边界判定、槽位种类计数。

## 决策与限制

1. **挖掘中间进度不持久化（核心决策）**：`apply_mining` 每次调用只执行一次敲击；未耗尽时返回 `{"item_id":"", "amount":0, "hardness_left":N, "depleted":false, "reason":""}` 且**不构造、不提交任何 patch**（进度是暂态，不入 snapshot、不入存档、不推进 revision）。调用方（后续世界/表现层工作包）必须自己暂存 `hardness_left`，下一击传入 `hardness = hardness_left` 的 cell_def 副本（副本，不改 ContentDB 定义）。**限制**：若调用方始终传入满硬度 cell_def，硬度 ≥2 的矿永远无法被破坏；进度暂存仅存在于运行时表现层，存档后丢失（重新开始敲击），这是切片接受的取舍。`test_progress_hit_does_not_persist_any_change` 用 canonical JSON 全等锁定该行为。
2. **负坐标边界**：切片世界 chunk 内坐标 0..31 非负，但 `apply_mining` 对 `cell.x < 0 or cell.y < 0` 在**构造 patch 之前**干净失败 `invalid_cell_coordinate`（不崩溃、不触碰 store/GameState）。source_id 构造 `gathering_%s_%d_%d` 因此不会引入 `-`，`GameState._is_stable_id` 校验恒可通过；测试 `test_negative_coordinates_fail_without_building_patch` 断言 `begin_calls == 0`。
3. **source_id 幂等**：`gathering_<chunk_id>_<x>_<y>` 对同一格稳定；重放提交返回 `already_applied` 且不推进 revision（GameState 既有语义）。
4. **store 注入模式**：patch 经 `Variant` 未类型化变量鸭子调用（契约 §0），`DuckPatch` 测试替身与真实 `StatePatch` 共用同一提交路径；`store == null` 时走 `GameState` autoload。注入路径不触碰 GameState（canonical JSON 全等断言）。
5. **背包槽位模型**：槽位数 = 背包物品种类数（每类一槽）；`stack_limit` 参数按契约签名保留未参与计算（未来分堆上限扩展点）。`can_carry` 对 `amount <= 0` 返回 false；容量判定 = 现有种类数 +（新物品是否需要新槽）≤ capacity。
6. **apply_mining 不做容量校验**：`add_item` 落盘前不调用 `can_carry`——容量是纯模型helper，容量约束的执行点归调用方/后续背包 UI 工作包（避免本包单方面引入契约外失败码）。
7. **cell_def 由调用方传入**：本包不依赖 ContentDB/WP12 数据文件；`ore_dust(2/0/starsoil_dust×2)`、`ore_shard(3/1/lumen_shard×1)`、`ore_core(4/2/resonant_core×1)`、`soil(0)` 映射以测试常量冻结，与 WP03 一致。
8. 新脚本与测试的 Godot `.uid` 文件随源文件一并提交（仓库既有约定）。
