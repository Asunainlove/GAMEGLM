### RED-1 同 id 多实例供电判定缺陷

半成品用 `powered_ids.has(building_id)` 判定"本次新建建筑"是否获电：同 id
旧实例获电会掩盖新实例断电（把 `powered=true` 误报给 Progression，多提交一个
冗余 flag patch）。先写
`test_place_chain_does_not_recommit_flag_for_unpowered_duplicate_effect_building`
（工坊 supply10 → echo#1 draw8 获电 → echo#2 draw8 仅剩 2 供给必断电）：

```text
- test_place_chain_does_not_recommit_flag_for_unpowered_duplicate_effect_building
    [Failed]:  [10] expected to equal [8]:  断电的新建回响舱不得触发 effect_flag 落账 patch。
    [Failed]:  断电的新实例必须被单调巡检记录。
Tests               360
Passing Tests       359
Failing Tests         1
```

（revision 10 = 建造 patch +1 与冗余 flag patch +1；且巡检同样因 `has()`
漏记断电新实例。）

修复：`_new_building_powered` 改为**计数差判定**——新建筑由
`GameState._apply_place_building` 保证追加在 `placed_buildings` 末尾，供给按
输入序分配使尾部追加不改变前缀分配，故该 id 在 `powered_ids` 中的出现次数
在新建筑加入前后"只增不减"，增量 > 0 当且仅当本次新建实例获电。
`_reconcile_effect_flags` 同步改为按 id 计数比较（placed 实例数 > 获电数 ⇒
存在断电实例）。

### 断言修正（非行为变更）

duplicate 测试最终断言修正为 `revision_before + 1`：建造 patch 本身必然
+1，冗余 flag patch 才会 +2。修复前实测 10（= 8+2），修复后 9（= 8+1），
计数判定生效。

## 决策与限制

1. **供电门控判定对象是"本次新建建筑实例"**（计数差，见 RED-1）。单独
   `has()` 在同 id 多实例时把旧实例的获电误记到新实例上。
2. **effect_flag 单调保持**：置位只发生在新建时按供电判定；断电不撤销已置位
   flag。该策略与 PowerGrid 语义自洽——供给按 `placed_buildings` 输入序分配
   且 GameState 的 placed_buildings 为 append-only，建筑建造时未获电 ⇒ 其
   之前无未占用供给 ⇒ 此后也不会获电，不存在"断电又复电"的状态需要撤销。
   `unpowered_effect_flags` 仅作只读观察记录（含本代理补的计数比较修复），
   表现层尚未消费。
3. **重启语义**：按冻结规格 `restart_requested → 删除 auto/manual 槽全部候选
   文件（.json/.json.tmp/.json.bak）→ get_tree().reload_current_scene()`。
   测试经 `session.save_root` 注入与 `SaveService.configure_root_for_tests`
   相同的隔离根；生产回退 `SaveService.DEFAULT_SAVE_ROOT`，两者一致。
   **限制**：`reload_current_scene()` 不重置 Autoload，生产环境重启后
   `GameState` 保留旧内存状态（读档失败走初始状态的前提不成立于 Autoload）。
   `src/state` 冻结且无公开 reset API，本包不允许越界改动——见"下一步"。
4. **删档实现镜像 `_slot_paths` 命名**：`SaveService` 无删除 API 且
   `src/save/**` 冻结，`GameSession._delete_save_slots` 以
   `.json/.json.tmp/.json.bak` 后缀镜像其命名约定（常量
   `SAVE_FILE_SUFFIXES` 注释已标注）。若 `_slot_paths` 命名漂移需同步此镜像
   （风险已记录，`_is_safe_slot` 保证槽名仅 ASCII 字母数字下划线连字符）。
5. **启动读档流**：`_ready` 中 `ContentDB.bootstrap` 后尝试
   `SaveService.load_slot("auto")`，`restore_snapshot` 自身只接受新鲜运行时
   （revision==0 且无已应用 patch 源，对应规格"revision==0 时"）；无档/失败
   返回 false 走初始状态。
6. **主菜单**：四按钮 `继续`（关菜单 + resume + `menu_resumed`）、`保存`
   （发 `save_requested`，菜单保持打开）、`说明`（切换 HelpPanel，原创中文
   操作说明：移动 WASD/方向键、采集 左键/Space、放置 右键/F、交互 E、背包
   I/Tab、覆盖层 O、菜单 Esc）、`重新开始`（发 `restart_requested`）。手动
   保存成功后 HUD `flash_notice("已保存", 1.5)`，轮询重渲染不覆盖通知窗口。
7. **启动屏淡出**：boot 完成后 Tween `modulate:a` 1→0（2s）后隐藏；节点与
   文案保留（test_app_bootstrap 锁定文案断言未动）；`finish_startup_fade`
   公开供测试跳过真实等待；淡出不阻塞输入（RED-2）。
8. **监听器保活**：信号替身宿主（`test_ui_hud.gd` 的 `_spy`、
   `test_integration.gd` 的 `_reload_spy`、`_fake`）均存测试实例字段，
   遵循 Godot 4 Callable 只持 ObjectID 的教训。
9. 提交拆分：先 `feat(ui)`（hud/场景/app 淡出 + test_ui_hud），后
   `feat(integration)`（game_session 门控/存档/重启 + test_integration +
   evidence），两个中间树均解析自洽；仅最终树做过全量门禁验证。
