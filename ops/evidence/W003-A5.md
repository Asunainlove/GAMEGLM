## 与 charter / 研究报告的对齐说明

1. **charter 对齐**：仅覆盖洛弦、弥砂两名成年原创核心角色（非目标不含第三角色，
   本合同未新增角色条目）；敌方替身 4 条严格对应 `data/content/combat_units.json`
   现有单位（`drift_swarmling`/`shard_husk`/`veinwarden_echo`/`lumen_leviathan`），
   未引入 charter 之外的新敌人；战斗替身三轨取值与 `schemas/encounter.schema.json`
   的 `front/mid/rear` 枚举一致。
2. **研究报告美术管线对齐**：采纳其 Canonical Reference → 表情差分 → Cut-in →
   UI 头像的引用母版流程（"不要每个表情重新生成完整人物"）、双分辨率视觉语言、
   `generated/raw → review → approved` 生产阶段与原始生成目录骨架；并按本仓库
   实际布局落位到 `docs/art/` 与 `assets/art/`。
3. **角色设定以工作包简报为准**：研究报告早期草稿中"洛弦，22 岁，女性"的人设
   与工作包锁定设定（洛弦为成年男性锚定工程师）冲突，本合同按工作包简报执行
   （charter 仅锁定"两名成年原创核心角色"，不锁性别），已在合同 4.1 节固化。
4. **角色语气实证**：表情与 Cut-in 表演要点逐条锚定 `data/events/*.json` 台词
   （洛弦：记录/读数/规程语气与"挡在人前"的保护欲；弥砂："土壤底下有一条河在
   唱歌"的共鸣感知与篝火照料感）；Cut-in 技能映射取自
   `data/content/combat_actions.json` 真实动作 ID（洛弦 `strike`/`resonate_pulse`，
   弥砂 `thread_bind`/`mist_calm`）。
5. **场景挂点实证**：对话头像 → `scenes/dialogue_box.tscn` 的 `DialogueBox/Panel`；
   HUD 头像 → `scenes/ui_hud.tscn` 的 `Hud`；战斗替身 → `scenes/battle.tscn` 的
   `Battle/Tracks`；动作帧 → `scenes/player.tscn` 的 `Player/Sprite`（现为
   ColorRect 占位，合同已注明由本动作集替换）。
6. **原创性合规（AGENTS.md）**：Style Bible 明文禁止出现任何现有游戏角色/服装
   组合/标志武器/Logo/UI/徽章、水印签名、在世画师署名风格；审批关卡 3 将原创性
   红线设为 `rejected` 触发条件；approved 前资产不得进场景——与 AGENTS.md
   "生成资产需 provenance 与人工批准"一致。

## Decisions and limitations

1. 战斗替身定为"像素化灰盒的最终美术形态"而非临时灰盒：合同按任务书要求给出
   5 状态 7 帧的完整帧包，直接可排产。
2. Boss 两阶段（`leviathan_p1/p2`）在同一 128×128 帧包内以加色叠加层
   `_phase2_overlay` 表达，不额外扩帧——保持任务书锁定的帧数结构。
3. 世界场景动作帧定为 48×48 序列帧（双态：朝右 + 翻转），骨骼动画在垂直切片
   不做；此为合同决策，若 W003 世界表现工作包另有布局需回改本节。
4. 本工作包为纯文档交付，无测试命令；验证方式为本文档与合同文件的存在性、
   git 干净提交与下述检查。
5. `docs/art/asset-registry.md`、`docs/art/prompts/`、`assets/art/**` 为合同约定
   的未来落位路径，本工作包不创建（不在允许路径内，且无实际资产产出）。
