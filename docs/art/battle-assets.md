## 1. 通用规范

### 1.1 双分辨率风格语言（像素单位 + 高清横幅）

延续研究报告锁定的"双分辨率视觉语言"——**这是有意设计，不是风格不统一**：

- **像素层（战斗单位 / 图标 / 单位级特效）**：严格像素网格作画，网格单位 = 2 px（画布上的最小色块为 2×2 物理像素），硬边、无抗锯齿、无渐变噪点；在 1280×720 视口下 1:1 显示。
- **高清层（场景底图 / 横幅 / 全屏特效）**：高清栅格作画，允许软渐变与光晕，但形体保持块面化概括（"高清像素感"），禁用细碎噪点笔刷；显示时由 1920 宽缩放 ×2/3 到 1280×720 视口。
- **两层统一靠**：同一色彩脚本（§1.2）、同一种星壤光（冷晶青 `#7FE7D0` 作全局发光语言）、同样的晶簇图形符号（六边形/棱柱切面）、底图与像素单位共用同一环境光方向（**主光来自画面右上，冷；补光来自矿脉发光，左下，暖或紫**）。
- **UI 语言**（横幅底图适用）：深色半透明面板 + 星壤发光线 + 非对称构图；横幅中央/侧翼必须预留文本安全区（文案由引擎渲染，不烧进图）。
- **Style Bible 关键词**（所有资产的设计母题）：星壤晶体、破碎世界、光学仪器、古代工程、宇宙考古、柔和冷暖对照、文明废墟。

### 1.2 色彩脚本（锚点色值）

| 锚点色 | 色值 | 用途 |
|---|---|---|
| 深空夜幕 | `#141B2E` | 全局暗部基底 / 横幅底 |
| 岩层暖棕 | `#6E4B37`（暗部 `#3A2E28`） | 矿区岩体、地面 |
| 琉砂暖金 | `#E8B36B` | 矿区星壤光、Boss P1 核心光（亮端 `#FFC46B`） |
| 冷晶青 | `#7FE7D0` | 星壤共鸣光、全局发光线 |
| 冷晶蓝 | `#9CD8FF` | 矿井深处冷光、Boss P2 核心光 |
| 失稳紫 | `#8A5CFF`（电弧亮紫 `#B18CFF`） | 失稳紫电、稳定度崩解 |
| 警示余烬橙 | `#E0784A` | 敌方识别色、伤害反馈 |
| 雾白 | `#DCE8E4` | 定神雾息、高光提亮 |

明度规则：像素层每资产主色 ≤ 5 阶明度；盟友整体偏冷蓝灰（灰盒期 `ALLY_COLOR` 的正式化），普通敌偏暖棕红，精英加冷晶青矿脉纹，Boss 双相位按 P1 暖金 → P2 冷晶蓝整体置换。

### 1.4 通用验收基线（每资产默认适用，条目内只写增量项）

1. **原创性**：通过 AGENTS.md 红线审查；不出现任何现有游戏剪影、Logo、水印、签名；角色均为明确成年人（不得幼态化）。
2. **尺寸与命名**：画布尺寸逐像素精确；文件名符合 §7.1 契约，目录符合 §7.2。
3. **像素网格**：像素层资产全部色块对齐 2 px 网格；导出后放大 800% 检查无半像素/抗锯齿灰边。
4. **透明度**：单位/图标/特效底为全透明，无白色废边（fringe）；底图/横幅按表要求透明或不透明。
5. **可读性**：剪影在灰度模式下仍可辨识阵营与姿态；图标缩至 24×24 仍可读。
6. **帧数与节奏**：帧数与条目帧清单一致；序列逐帧检查无跳色、无轮廓抖动（除有意设计的震颤帧）。
7. **色彩**：落在 §1.2 锚点色的邻域内，不引入色表外的饱和色。
8. **文本安全区**：横幅/底图不得把文案烧进图；UI 挂点区域（顶部横幅带、左上回合标签、左下行动菜单）保持低对比。

优先级定义：**P0** = 三场固定遭遇与 Boss 战的最小可读集（缺则战斗不可发布）；**P1** = 反馈增强（可先用灰盒/纯色占位）。工时单位为"人时"（单人直接生产 + 自检 + 溯源登记，不含协调者审批）。

## 2. 单位战斗精灵（6 条 / 56 帧）

通用约定（适用于本节全部条目）：

- **用途与挂点**：替换 `battle_scene.gd` `_build_unit_node` 中的 56×40 灰盒 `Box` 节点；锚点 = 单位节点原点，精灵**底边中心**对齐灰盒底边（原点下方 +20 px），名称/血量 Label 仍由引擎渲染在精灵上方，故构图顶部 24 px 内不放置关键形体。
- **帧清单结构**：每单位 `idle` 2 帧 / `attack` 3 帧 / `hit` 1 帧 / `death` 2 帧，共 8 帧；Boss 另有 P2 全套（§2.6）。帧时长建议（引擎侧，§7.3）：`idle` 2 fps 循环（两帧=一次呼吸，配合错帧实现群集感）、`attack` 8 fps 不循环（≈0.375 s）、`hit` 6 fps 单帧（引擎可停留 0.15 s）、`death` 6 fps 不循环、停在末帧。
- **朝向**：盟友面朝右，敌人面朝左；攻击帧的动作矢量必须指向对面阵营。
- **验收增量**：除 §1.4 外——idle 两帧仅允许呼吸级位移（≤2 px），保证挂机不闪瞎；attack 第 1 帧（`attack_01`）是打击帧，必须是全序列最大形变帧。

## 7. 数据契约

### 7.1 文件命名契约

三种形式（全部 snake_case，符合项目稳定 ID 纪律）：

1. **动画序列**：`<asset_id>_<state>_<NN>.png`。`state ∈ {idle, attack, hit, death}`（单位）；特效以 `fx` 为 asset_id、state 槽承载效果名（如 `fx_strike_hit_01.png`）。帧号 `NN` 两位零填充、从 `00` 起。
2. **静态图**：`<type>_<id>.png`——图标 `icon_<action_id>.png` / `icon_cost_badge.png`，底图 `bg_<id>.png`，横幅 `banner_<id>.png`。
3. Boss 两阶段经目录区分，文件名不变（§7.2）。

示例：`luoxian_fighter_attack_01.png`、`lumen_leviathan_idle_00.png`（phase1 与 phase2 目录下同名）、`fx_destabilize_arc_02.png`、`icon_resonate_pulse.png`、`bg_mine_depths.png`、`banner_victory.png`。

### 7.3 SpriteFrames 与导入建议（供 A4/引擎执行包采用）

- **导入**：像素层纹理压缩选 Lossless，关闭 mipmaps；过滤默认 Nearest（项目级为战斗像素资产设 `texture_filter = NEAREST`）；底图/横幅用 Linear。
- **单位 SpriteFrames**：每单位一个 `.tres`，置于该单位目录（如 `units/luoxian_fighter/luoxian_fighter.tres`），动画命名与帧清单一致：`idle`（loop，2 fps）、`attack`（non-loop，8 fps）、`hit`（non-loop，6 fps）、`death`（non-loop，6 fps，末帧驻留）。
- **Boss**：`units/lumen_leviathan/phase1.tres` 与 `phase2.tres` 两份（动画名同上），相位切换时整体替换 `sprite_frames`——替换动作必须发生在 `fx_phase_burst` `_00` 全屏白闪帧内。
- **特效**：每效果一个 SpriteFrames（`fx/fx_<effect>.tres`），一次性播放后 `queue_free`；`fx_guard_shield` 例外，循环播放直至护盾失效。
- **挂点复核**：单位精灵锚点 = 底边中心对齐灰盒底边（单位原点 +20 px）；替换灰盒时保留名称/血量 Label 渲染逻辑；当前灰盒三轨行距 96 px 若与精灵高度冲突（尤其 Boss 256 高），由 A4 调整舞台常量，资产侧以 §3 三轨基线为准。

### 7.4 溯源与审批（AGENTS.md 强制）

- 每个资产入库前在**溯源登记**（建议路径 `docs/art/battle-provenance.md`，由首个美术执行包建立）登记一行：`asset_id / 生产方式（生成工具+模型或画师）/ prompt 或参考记录位置 / 日期 / 审批人 / 状态`。
- 状态流：`draft → in_review → approved`；**未达 `approved` 的资产不得被任何场景引用**（引擎侧以目录或资源标记区分）。
- 审批要点即 §1.4 验收基线逐项勾选 + 原创性红线；审批人必须是人工（协调者或其指定人），不得由生成流程自批。

### 7.5 与并行包的契约点

- **A5 角色规范**：`luoxian_fighter` / `misa_weaver` 的 128×128 战斗形态与 A5 同剪影同配色；若 A5 与本规范出现冲突，以先发布并经协调者仲裁的版本为准，另一方修订。
- **W003-A4 战斗表现**：本规范的单位挂点/帧节奏（§7.3）与横幅尺寸（§6）是 A4 实现的表现层输入；A4 的相位横幅触发帧应与 `fx_phase_burst` `_00` 对齐。
- **数据侧**：遭遇→底图绑定（`background_id` 建议字段）与"未 approved 资产不可引用"的校验属数据/引擎侧决策，本规范仅提出需求，不改动任何数据文件。
