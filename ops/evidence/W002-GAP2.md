# W002-GAP2 手工矿井/Boss 区

## 目标
章程 Locked scope 第 1 条"4×2 Chunk 琉砂海地区 + 一个手工矿井/Boss 区"——在 chunk_3_1 实现手工 authored 矿井（固定布局，无 RNG）+ Boss 房空间载体与触发链。

## 初始现状
接手中断半成品：7 文件修改 + 2 测试文件 + 事件数据（共 169 行核心改动 + 625 行测试），未提交、无 evidence。

## 实现要点
- `ChunkData.generate_mine(chunk_id)`：常量表驱动（MINE_WALL_RECTS 8 块岩壁矩形 + MINE_ORE_VEINS 矩形，矿 80 格，dust/shard/core=3:4:3）；入口走廊 y=8..9 西端开口衔接 chunk_2_1；竖井 x=12..13；中央矿脉腔 x=6..25,y=13..21；Boss 房 x=10..19,y=22..31（10×10 开阔无矿）。`CELL_DEF_ROCK_WALL`：hardness 0 + min_tier 9 双保险不可采不可破坏。确定性由常量表保证（不依赖 world_seed）。
- `world.gd`：chunk_3_1 用 generate_mine 覆盖程序生成；`chunk_origin` 辅助换算世界↔本地坐标。
- `world_renderer.gd`：rock_wall 专属深褐 source (0.24,0.2,0.16)。
- 触发链（`game_session.gd`）：`mine_entry_check`——玩家格首次进入 chunk_3_1 且 done 未置 → 走既有事件流程展示 `event_mine_threshold`（台词 + effect mine_entered + effect due_encounter encounter_leviathan_due，与"双胜+policy"路径写同一 flag 幂等）；Boss 房（世界格 y≥54）触发既有 set_player_position 检查点（reason=boss_room_enter，幂等由 patch 通道保证）。矿井入口事件优先级高于 due_event 链（入口台词应即时呈现）。

## 决策与限制
- 矿井入口事件不经 Progression.due_event 链（src/progression 冻结裁定）：位置触发放 game_session，flag 幂等使两条 leviathan 触发路径共存。
- rock_wall 不可建未在 BuildingRules 显式拒绝——cell_def min_tier 9 使采集永不可能，建筑占位判定依赖 placed_buildings 与 destroyed，不影响。
- 无新战斗单位（复用 lumen_leviathan）；Boss 房仅为空间载体与检查点。
