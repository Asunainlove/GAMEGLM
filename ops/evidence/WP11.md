## CJK 字体方案与限制

- 方案：主题 `default_font` 使用 `SystemFont` SubResource，`font_names = ["Microsoft YaHei UI", "Microsoft YaHei", "SimHei"]`，基础字号 14。Windows 离线环境直接命中系统字体，无需打包字体文件（原创资产零拷贝风险）。
- 限制 1：非 Windows 平台（如 Linux CI）上这三个字体名不命中，`SystemFont` 回退到引擎默认字体，中文可能显示为方块或由 `allow_system_fallback` 决定回退效果。本包验收环境为 Windows（win32），已按锁定基线执行；跨平台字体兜底记入待办。
- 限制 2：headless 测试只断言了 `SystemFont` 的配置契约（字体名列表、字号、样式资源类型），不断言实际字形渲染效果；需要人工在带窗口运行时目检。
- 限制 3：`Microsoft YaHei UI` / `Microsoft YaHei` / `SimHei` 是 Windows 系统字体名引用而非随包分发资产，不构成对第三方字体文件的再分发。

## 架构与决策记录

- **只读表现层**：`Hud` 仅调用注入的 `snapshot_provider`（缺省 `GameState.snapshot`）读取快照；`_unhandled_input` 只翻转自身节点可见性与 `get_tree().paused`（引擎级 UI 状态，非持久状态）；无任何 patch/commit 调用。测试 `test_refresh_never_mutates_injected_snapshot` 用按引用返回的假快照做深比较锁定该约束。
- **注入保活**：遵循 Godot 4 教训，测试把 `FakeSnapshotProvider`（RefCounted 内部类）存入测试实例字段 `_fake` 再取 `Callable`，避免临时对象释放导致注入静默失效；`test_refresh_renders_inventory_bar_with_injected_names` 同时断言 `calls >= 1` 证明注入真的被调用。
- **轮询**：`_ready` 时代码构建 `PollTimer`（wait_time 0.25、repeat、autostart），超时后仅在 `revision` 变化时重渲染；`refresh()` 公开方法无视缓存强制重渲染。`Hud` 根 `process_mode = ALWAYS`，暂停时轮询与菜单输入均可用。
- **`objective_for` 语义**（静态、纯函数，表驱动测试锁定）：任一未决遭遇（`encounter_<id>_due` 且未 `won`）优先提示为即时威胁；随后按里程碑链条返回首个未完成目标：落地事件 done → 勘探采集（完成于首次采矿事件或已放置锚块）→ 放置第一座锚块 → 建立锚居工坊（完成于工坊放置或引导事件）→ 应对漂移群威胁 → 驻地抉择 → 方法与政策抉择（approach 与 policy 均需完成）→ 面对辉砂巨兽 → 见证余辉结局；无进度或全部完成回退 `"探索世界"`。里程碑完成条件取"事件 done flag 或具体成就"的或运算，兼容事件标记与建造顺序的先后差异。
- **背包栏 "+n" 语义**：超过 8 种物品时第 9 个槽汇总为 `+n`，n = 未展示的物品种类数（不同种类数量无法加总成一个有意义的量）；槽位按 item_id 字典序排序保证确定性，数量 ≤0 的条目不展示。
- **主题挂载**：`CanvasLayer` 无 theme 属性，主题分别挂在四个直接 Control 子节点（InventoryBar/ObjectiveLabel/InventoryPanel/MenuPanel）上，测试逐一断言。
- **菜单"继续"**：关闭菜单并解除暂停后发出 `menu_resumed`，供后续集成层（app.gd）消费；"说明"按钮就地切换灰盒帮助文案。
- 未实例化进 `app.tscn`（禁改）；场景按契约 §4 独立交付，挂接属集成工作包。
