## 决策记录

1. **shock_trap 渠道（任务书指定，须记录）**：契约 §7 给共鸣织机列了两条配方（2×辉砂晶片→定神雾；2×辉砂晶片+1×共鸣核→震颤陷阱），但冻结 schema `building-recipe.schema.json` 的 `recipe` 只支持**单输入**配方（`input_item_id` 单值、`additionalProperties: false`），无法表达双输入。按任务书裁定：震颤陷阱的获取渠道改为 **`event_first_anchor` 的 grant_items（×1）+ 遭遇掉落**。落地上，`shard_husk`（碎壳游荡者，任务书掉落清单之外的唯一增量）掉落追加 `shock_trap×1`，使其在 `encounter_husk_ambush` 形成"用陷阱→捡陷阱"的循环；任务书各单位掉落清单全部原样保留。若协调者改用多配方 schema，只需恢复织机配方并删除该条 drop。
2. **Boss 相位 id**：任务书逐字给出 `phases:[{id:"leviathan_p1", at_hp_ratio:0.5, action_ids:[lumen_surge, vein_quake, strike]}]`，按其落地（§7 的 `leviathan_p1/leviathan_p2` 两阶段中，p1=基础行动池开局阶段、p2=0.5 血切换后的行动池；WP10 引擎测试夹具曾以 `leviathan_p2` 作占位相位 id，此处以任务书为准，两个 id 均在 §7 白名单内，未发明新 id）。相位 id 仅出现于战斗日志，不影响任何持久状态。
3. **`due_encounter` 携带 trigger_flag 而非遭遇 id**：任务书与冻结契约一致（§5 `EventRunner.apply_effect_step` 将 due_encounter 值写为 flag，由 WP13 按 trigger_flag 门控；§7 冻结 `encounter_first_drift_due` 等触发旗标）。**已知跨包不一致**：WP01 的 `ContentDB.validate_refs` 把该字段当遭遇 id 校验，故对本数据包报告恰好两条 dangling（`event_first_mining`/`event_workshop_guide`）。测试精确断言"悬空引用必须且仅为这两条"，其余引用（items/recipe/cost/drops/action_ids/unit_ids/item_ids）全部要求可解析。该不一致只能由协调者裁定（属 WP01 路径）。
4. **station_mode_exploit 双 delta 截断**：任务书要求该选项携带两条 relation_delta（洛弦 affection −10 与 trust −5），但冻结 schema `event.schema.json` 的 `relation_delta` 是**单对象**（且 `EventRunner._deferred_relation_ops` 也只读单条）。数据落地首条（luoxian.affection −10），trust −5 无法在冻结 schema/运行时内表达，待协调者裁定（扩展 schema 或集成层补写）。
5. **遭遇 ally 道具表示**：schema 用 `item_ids: Array[String]` 表达 ally 携带的沙盒道具；数量按**出现次数**计（`sedative_mist×2` → 重复两项）。`EXPECTED_ALLY_ITEM_COUNTS` 断言与 WP13 `start()` 的 items 字典装配一一对应。
6. **敌方行动池**：四个敌方单位的 action_ids 均含无 cost 行动 `strike`（测试断言），保证确定性 AI 永有可支付行动。
7. **事件结构**：每文件单 JSON 对象（`EventRunner.load_events_from` 要求）；台词 2–4 行/事件、choice 2–3 选项；`policy_sanctuary` 携带 `requires_trust: 40` 且文案明示"需要洛弦的信任达到 40"（EventRunner 的信任门按 luoxian.trust 校验，与 §7 一致）。

## 限制

- 全部中文文案为原创，未复制任何现有作品的角色/术语/台词；角色洛弦（冷静理性的锚定工程师）与弥砂（活泼敏锐的矿脉共鸣者）为原创成年人设定。
- 遭遇为一次性叙事节点（due flag 门控），掉落渠道相应为一次性；`shock_trap` 全局获取量上限约 2（事件 1 + husk 掉落 1），垂直切片范围内够用。
- `leviathan_p2` 在数据中无独立条目（见决策 2）；若 WP13/WP14 需要按 §7 字面双条目相位，需要协调者给出一句话裁定。
- `ContentDB.validate_refs` 对 `due_encounter` 的 id/flag 语义不一致（见决策 3）与 `station_mode_exploit` 第二条 delta 无法表达（见决策 4）均需协调者处置，不阻塞本包。
