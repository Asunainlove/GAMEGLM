## 4. due_event 链插入序（15 → 24）

| 7-11 | （既有 5 项不变）husk_aftermath → station_mode → echo_resonance → approach → policy | （不变） | 不变 |

### 双守卫设计说明（与任务规格单 flag 的偏差，逐条）

任务规格的 `requires_flag` 保留在事件 JSON 层（EventRunner.available_events 口径）；链上守卫额外追加第二/第三 flag，唯一目的：**冻结集成测试（tests/unit/test_integration*.gd 禁改）用「直接 patch 单一 flag」模拟状态，新事件若只守单 flag 会在其结局/软锁死/矿井回归路径上被误触发**。第二守卫一律选取「只有经对话链真实达成才会置位」的 flag：

- `diplomat_envoy` +`echo_chamber_active`：真实游玩中 approach_diplomatic 必然发生在 station_mode 事件后（其前置即 echo_chamber_active）；集成软锁死回归测试直接 patch `diplomatic_stance` 但不含该 flag。
- `leviathan_pact_pre` +`encounter_leviathan_due`：两者由矿井入口事件同一 effect 步同时置位；矿井集成测试直接 patch `mine_entered`（不含 due）并断言无事件。
- `final_ascent` +`encounter_leviathan_due`：胜利后 due 旗标保留（EncounterDirector 胜利只写 on_victory_flag，不清触发旗），等价于「走过 Boss 链」；结局集成测试直接 patch 三胜但不含 due。
- `epilogue_exploited` +`world_response_exploited`：该 flag 仅在对话链真实选择 exploit 时由 `Progression.world_response_ops` 落账；结局集成测试直接 patch `station_mode_exploit`。
- `epilogue_sealed` +`echo_chamber_active`：seal 选择必然发生在 station_mode 事件内；同测试直接 patch `station_mode_seal`。
- 两个 epilogue +`encounter_leviathan_won`：GREEN 阶段链走查（RED 测试）发现 exploit/seal 线会在 Boss 战前提前泄漏终章，故补第三守卫（TDD 回归的实际收益）。

## 7. 限制

1. **单事件 line 步上限 4**：冻结内容契约测试（test_content_data `_validate_event_def`，禁改文件）限定 2..4 个 line 步；任务期望的「每事件 4-8 行台词」在 line 步口径下封顶 4，超出部分以 choice 问句与选项文案补足（pact_pre 达到 8 条/事件）。
2. **双守卫偏差**：§4 所列链上守卫在任务规格单 flag 之外追加 flag，系为保持禁改的冻结集成测试语义（其 flag 集下 due_event 必须为空）；全部第二守卫在真实游玩中与主守卫同时/更早达成，不产生游玩路径缺口。
3. **symbiosis 线无终章感言**：任务仅要求 exploit/seal 两份 epilogue；共生线以双结局事件收束，epilogue 位次自然空过。
4. **45-60 分钟目标非本包独力可达**：F1 的时长缺口由台词、经济循环、世界面积、战斗规模等多个维度构成；本包仅覆盖事件台词维度（+58% 单周目台词量），经济与世界面积归属其他工作包。
5. **验证环境干扰记录**：本工作区与并行包共享开发机。验证期间发生两次环境性干扰：(a) `/tmp` 下通用日志文件名与并行进程互覆，改用 `gap5_w003a1_*` 专属日志名后复测；(b) Verify-Slice 首跑中 `test_content_db` 固件树引导出现 3 例瞬时失败（内容装载为空，属磁盘/进程争用症状，与本包改动无关——同套件在本包代码下已 462/462 通过），重跑即恢复并通过全部四道闸门。两次均未掩盖真实回归：所有失败均经复跑确认后归因。
6. 矿井入口事件 `event_mine_threshold` 为位置触发（GameSession 自检），优先级高于 due_event 链且不在链上，维持 W002-GAP2 冻结语义不变。
