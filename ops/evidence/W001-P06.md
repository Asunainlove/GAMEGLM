## 为何解冻 src/state 与 src/save

P05 evidence 明确记录了两个越界遗留缺陷，本包是唯一允许修掉它们的收尾包：

1. **`reload_current_scene()` 不重置 Autoload**——P05 重启链只删文件 + 重载
   场景，`GameState` autoload 的内存状态原样残留，"重启后读档失败走初始
   状态"的前提对 Autoload 不成立（P05 evidence 决策与限制第 3 条）。修复
   必须提供公开 reset API，即解冻 `src/state`：新增
   `GameState.reset_to_initial()`。
2. **删档镜像 `_slot_paths` 命名**——P05 的 `GameSession._delete_save_slots`
   以 `SAVE_FILE_SUFFIXES` 常量镜像 `.json/.json.tmp/.json.bak` 后缀命名，
   存在命名漂移风险（P05 evidence 第 4 条）。修复必须给 `SaveService` 提供
   删除 API，即解冻 `src/save`：新增 `SaveService.delete_slot(slot)`。

两处 API 落地后，`GameSession` 删除镜像常量、`save_root` 注入点与
`DirAccess` 直接操作，删档只经 `SaveService.delete_slot`。

## 新鲜约束与 reset 的交互

`GameState.restore_snapshot` 的守卫是：

```gdscript
if int(_state["revision"]) != 0 or not (_state["applied_patch_sources"] as Array).is_empty():
    return AppResult.failure("restore_requires_fresh_state", ...)
```

`reset_to_initial()` 直接 `_state = _make_initial_state()`——与 `_init` 同一
构造函数，revision 归 0 且 applied_patch_sources 清空，因此重置后守卫的两个
条件同时重新满足，restore_snapshot 恢复可用（启动读档流在场景重载后重走
`_ready → _try_load_autosave → restore_snapshot`，此时状态必须是新鲜的）。
测试 `test_restore_snapshot_is_unblocked_by_reset_to_initial` 先证
`revision>0` 时 restore 被拒（`restore_requires_fresh_state`），reset 后同一
快照 restore 成功，交互双向锁定。文档注释明确：reset 仅用于"重新开始"
生命周期，常规 gameplay 必须走 `begin_patch()/commit()`。

## 实现要点

1. **`GameState.reset_to_initial() -> void`**（src/state/game_state.gd）：
   `_state = _make_initial_state()`，紧邻 restore_snapshot 放置（同为生命周期
   方法，与 patch 流明确区分），文档注释标注仅限"重新开始"生命周期。
2. **`SaveService.delete_slot(slot: String) -> AppResult`**（src/save/
   save_service.gd）：`_is_safe_slot` 校验（与 save/load 同一守卫，路径穿越
   防护一致）→ **复用同一 `_slot_paths` 私有路径构造**（零镜像）→ 逐个删除
   存在的 primary/.tmp/.bak（`DirAccess.remove_absolute`，与 save_slot 的
   `rename_absolute` 同为绝对路径 API）→ 返回 `AppResult.success(null,
   "deleted", {"slot", "removed"})`；无文件时 `success(null, "absent",
   {"slot", "removed": 0})`；删除失败 `failure("slot_delete_failed", ...)` 且
   保留其余候选。save_codec 侧零改动。
3. **restart 链**（src/integration/game_session.gd）：`_on_restart_requested`
   改为 `_reset_persistent_state()`（目标解析与 `_try_load_autosave` 同一注入
   契约：store 优先，null → GameState autoload）→ `_delete_save_slots()`（逐
   槽调 `SaveService.delete_slot`，失败仅 push_warning 不阻断重载）→
   `_reload_current_scene()`。删除 `SAVE_FILE_SUFFIXES` 常量、`save_root` 注入
   变量与 `DirAccess` 镜像逻辑；test_integration.gd 同步移除两处
   `session.save_root` 注入（存根路径统一走 `SaveService.configure_root_for_tests`，
   删档与生产同走 SaveService）。

## 限制与后续

1. `reset_to_initial` 是公开 API，任何代码均可调用；本包以文档注释约束其
   仅用于"重新开始"生命周期。若后续需要更强约束，可在 P07+ 引入来源标记，
   当前切片不做（避免超出小包范围）。
2. `_delete_save_slots` 对单槽删除失败只 push_warning（删档尽力而为，场景
   仍重载）；与 P05 语义一致。`delete_slot` 本身在任一候选删除失败时返回
   失败并保留其余候选，供调用方决策。
3. GUT 运行时偶见 GUT 更新探测器 403（GitHub API 限流）日志噪声，不影响
   测试结果与退出码。
4. 后续：P07+ 可让 HUD/主菜单在重启流程中展示"已重置"反馈；或在
   `delete_slot` 增加 details 中各候选的存在明细。
