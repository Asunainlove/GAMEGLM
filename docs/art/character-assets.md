## 0. 文档定位与适用范围

1. 本规范覆盖垂直切片全部角色向美术资产：两张母版（Canonical Reference）、表情差分、Cut-in、UI 头像、像素化战斗替身精灵、世界场景动作帧。
2. 所有资产为**原创设定**：不得参考、模仿或复现任何现有游戏的角色、剪影、服装组合、标志武器、术语、Logo、UI 或徽章；不得指定任何在世画师的画风。`AGENTS.md` 的全部原创性条款对本合同每一张图生效。

## 1. 统一风格基准（Style Bible，随每张图下发生效）

### 1.1 双分辨率视觉语言

本项目采用有意设计的双分辨率语言，**不是**美术不统一：

- **环境 / 世界场景：像素或像素感栅格**（Tile、建筑、世界内角色动作帧）。
- **角色表现 / UI：高清二次元栅格立绘**（母版、表情、Cut-in、头像）。

统一依靠以下不变量（每张高清图与每帧像素图都必须遵守）：

1. 同一份世界色彩脚本：沙尘暖褐 + 星壤冷光。
2. 同一种"星壤光效"：冷色青碧/淡金辉光，边缘柔和衰减。
3. 同一套服装材质逻辑：功能性探索装备 + 幻想材料，高清洗染与像素成色一一对应。
4. 同一套图形符号体系：锚形、环纹、稳压表盘、共鸣晶体。
5. 高清立绘边缘加入与所在场景一致的环境光（矿道暖橙、地表冷蓝）。

## 2. 通用生产条款

1. **命名**：全 `snake_case`，与资产 ID 一致；差分后缀见各条目；禁止中文、空格、大写。
2. **格式**：高清栅格一律 PNG（含 8-bit Alpha）；像素帧 PNG（禁止 JPEG/WebP 入库）。
3. **透明底**：除 Cut-in（自带完整背景）外全部透明底；禁止残留白边、半透明光晕矩形。
4. **人物一致性**：所有衍生图必须引用对应 Canonical Reference 母版（参考图流程），禁止每次从纯文字重新生成整人；发型、服装、配色、比例（约 7 头身成年人）为锁定不变量。
5. **导入验证**：每个批次交付前在 Godot 4.7.2 中导入一次，确认无资源警告、尺寸读取正确。
6. **工时单位**：人时（含提示词/参考图准备与返工余量），按 P0 → P1 → P2 顺序排产。

## 4. 高清资产条目

### 4.1 Canonical Reference（角色母版）

#### ART-001 `luoxian_canonical` — 洛弦母版

- **用途与挂点**：全体洛弦高清资产的唯一参考母版；不直接进游戏，登记入 `docs/art/references/characters/` 供后续生产引用；角色页立绘（未来 UI）裁切自本条目。
- **尺寸与格式**：3 张独立 PNG，各 1920×1080（1080p），8-bit Alpha 透明底；文件 `_front` / `_three_quarter` / `_back`。
- **风格语言**：原创成年男性锚定工程师；冷静、克制、精密的体态语言；精细线稿 + 赛璐璐上色；气质关键词"秩序、账本、稳压器"。
- **构图要素**（三视图必须共享同一套设计）：
  - 体貌：成年人，短发（深灰黑），约 7 头身，站姿端正。
  - 服装：深蓝工装外套 + 同色长裤，铜金色功能扣件与滚边；护目镜推在额前（台词实证道具）。
  - 稳压装置：左肩至前臂的稳压管路与一块铜金色表盘（淡金辉光），为本角色唯一强发光点。
  - 随身物：腰侧记录板（他的"账本"），手持振锚锤/探杆收于背后（正面视图可见锤头轮廓）。
  - 三视图角度：正面（0°）、3/4 侧面（约 45°，主视图）、背面；三张图脚底基线与身高比例完全一致。
- **差分清单**：无（母版不带表情差分，统一为"平时"神态）。
- **验收标准**：三视图身高误差 ≤2%；色板命中 1.3 节洛弦行；稳压装置三视图位置逻辑连贯；透明底无杂像素；通过 Style Bible 原创性检查（无任何现有游戏元素）；Godot 导入无警告。
- **优先级 / 预估工时**：P0 / 24h。

- **用途与挂点**：`scenes/ui_hud.tscn` → `Hud`（CanvasLayer）战斗底部头像卡与状态区；圆形遮罩内显示。
- **尺寸与格式**：128×128 PNG 透明底，**圆形裁切已在图内烘焙**（圆外 alpha=0），每角色 1 张。
- **风格语言**：同母版 `_neutral` 表情；允许在 128px 下做像素级简化但不能改设计。
- **构图要素**：由对应 256 `_neutral` 头像缩放取脸部中心生成；圆内边缘 2px 的角色主色描边（洛弦深蓝、弥砂暖橙）以区分阵营归属。
- **差分清单**：无（受击/死亡状态由 UI 层灰化处理，不出差分）。
- **验收标准**：128×128 精确；缩到 64px 仍可分辨两人；圆形边缘无锯齿带。
- **优先级 / 预估工时**：P1 / 1h（各，衍生加工）。

## 5. 像素化战斗替身（灰盒最终形态）

### 5.0 公共规格（ART-013 ~ ART-018 共同遵守）

- **用途与挂点**：`scenes/battle.tscn` → `Battle/Tracks`（Node2D）三轨单位显示。轨道与取值见 `schemas/encounter.schema.json` / `schemas/combat-unit.schema.json`（`front` / `mid` / `rear`）。
- **尺寸与格式**：每帧 128×128 PNG 透明底；每单位 7 帧基础包：待机 2（`_idle_0/_idle_1`）、行动 3（`_act_0/_act_1/_act_2`）、受击 1（`_hit_0`）、倒地 1（`_down_0`）。
- **播放约定**（供战斗表现实现参考）：待机 3fps 循环；行动 10fps 单次；受击单帧停留 200ms；倒地帧常驻。
- **风格语言**：像素化替身的**最终美术形态**（非临时灰盒）：中高密度像素（1px=1px 绘制，禁止糊化缩放），轮廓清晰、剪影优先；配色沿用 1.3 节色板与敌对单位冷色规范；发光统一用 1 色邻接亮阶表达。
- **三轨空间约定**：全单位同一 128×128 画布，绘制体高一致；前后层次由场景定位与缩放表达——front ×1.0 / mid ×0.9 / rear ×0.8，并按轨向上偏移；本条约束场景侧，绘制侧不做缩放。
- **验收标准**：帧尺寸精确 128×128；同单位各帧角色锚点（脚底中心）像素对齐；受击帧为待机帧的白闪变体（允许程序化闪白替代，此时受击帧=待机帧）；倒地帧明确表达失去意识而非死亡血腥；通过 Style Bible 原创性检查。

#### ART-013 `luoxian_battle_sprite` — 洛弦战斗替身（front，speed 6）

- **构图要素**：深蓝工装剪影 + 铜金稳压肩件（1 发光点）；持振锚锤；行动 3 帧为"举锤—下压锚定—余振"，对应 `strike`/`guard` 的通用发力。
- **差分清单**：7 基础帧。
- **验收**：公共规格 + 剪影与弥砂一眼可分（重工装方剪影 vs 轻装斜剪影）。
- **优先级 / 工时**：P0 / 12h。

#### ART-014 `misa_battle_sprite` — 弥砂战斗替身（mid，speed 5）

## 7. 管线与审批

### 7.1 生产目录与文件落位约定

```text
docs/art/
├─ character-assets.md          ← 本合同
├─ prompts/                     ← 每批次使用的最终提示词存档（文本）
├─ references/characters/       ← approved 母版参考副本（供后续生产引用）
└─ asset-registry.md            ← 来源登记表（新建时按 7.2 字段）

assets/art/
├─ generated/
│  ├─ raw/                      ← 生成/绘制原始输出，禁止进场景
│  ├─ review/                   ← 通过自检、待人工审
│  └─ approved/                 ← 人工批准，等待落位
├─ characters/
│  ├─ luoxian/
│  │  ├─ canonical/   expressions/   cutins/   avatars/   battle/   actions/
│  └─ misa/                     （子目录结构同 luoxian）
└─ units/                       ← 非角色战斗单位（敌对）
   ├─ drift_swarmling/battle/
   ├─ shard_husk/battle/
   ├─ veinwarden_echo/battle/
   └─ lumen_leviathan/battle/
```

文件名 = 资产 ID + 差分后缀（如 `luoxian_expr_resolved.png`、`lumen_leviathan_battle_act_1.png`）。场景只允许引用 `assets/art/characters/**` 与 `assets/art/units/**`；`generated/**` 任何时刻不被场景引用。

### 7.2 来源登记表字段（每张资产一行）

| 字段 | 说明 |
|---|---|
| `asset_id` | 本合同资产 ID + 差分后缀 |
| `tool` | 产出工具/方式（如具体生成工具名、手绘） |
| `prompt_ref` | 提示词存档文件名（指向 `docs/art/prompts/`，需含参考图说明） |
| `date` | 产出日期 |
| `producer` | 生成者/绘制者 |
| `source_files` | raw → review 的文件路径轨迹 |
| `status` | `raw / review / approved / rejected` |
| `approver` | 人工审批人（approved 必填） |
| `approve_date` | 批准日期 |
| `notes` | 返工记录、原创性自检结论 |

### 7.3 审批关卡（`AGENTS.md` 强制）

1. **Gate 1 自检（进入 review）**：尺寸/Alpha/命名/锚点合规，Style Bible 原创性自查通过。
2. **Gate 2 人工视觉 QA（review → approved 候选）**：逐条对照各条目验收标准；角色一致性对照母版；双分辨率语言统一性检查（与场景截屏并排比对）。
3. **Gate 3 人工批准（approved）**：由协调者或其指定人批准并在登记表签字（approver/approve_date）。**未 approved 的资产不得复制进 `assets/art/characters|units`，不得被任何场景引用**。
4. 原创性红线（任一触发即 `rejected`）：与现有游戏角色/剪影/标志设计雷同；出现 Logo、UI、徽章、水印、签名；模仿在世画师署名风格。
5. 每批次收尾：更新登记表、提示词存档，并在 evidence 中记录"本批 N 张、approved M 张、rejected K 张及原因"。
