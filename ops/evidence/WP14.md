## 决策与限制

- **done flag 双前缀**：EventRunner 的 `EVENT_DONE_FLAG_FORMAT = "event_%s_done"` 以完整事件 id（本身带 `event_` 前缀）填充，故实际 flag 为 `event_event_<name>_done`（WP08 测试已锁定该形状）。Progression 复用同一模板常量并有测试逐字比对两包常量，杜绝模板漂移。
- **跳过语义**：`due_event` 按"第一个未 done 且前置满足者"实现——前置不满足的事件被跳过、继续检查后续（任务书"前置不满足时跳过返回后续"）。典型中间态（prologue done、尚未采集）因此返回 `""`（链上无人就绪），测试已锁定。
- **一次性范围**：仅 `mined`（任务书明示）与 `encounter_leviathan_due`（任务书"幂等"）做"已置即成功跳过、不 begin_patch"；`built` 的锚块/工坊 flag 重复置位无害且任务书未要求跳过，保持 spec 字面行为（同 revision 重放仍受 source_id 幂等保护）。
- **Leviathan 门控只读 state**：`encounter_won`/`policy_chosen` 的组合条件（两场胜利 + 任一 `policy_*`）一律读传入快照的 flags，payload 中的 id 仅做格式校验——与任务书"同上检查"逐字一致。集成层须在 EventRunner/EncounterDirector 落账**之后**取新快照再调 react，否则条件尚未可见（stale snapshot 不置 due flag，属契约语义而非缺陷）。
- **`policy_*` / `station_mode_*` / `approach_*` 前缀匹配**：按任务书"任一 xxx_* flag"以 `begins_with` + 值为 true 判定；契约 §7 冻结的选项 flag 全部落入对应前缀，且 done flag 均以 `event_` 开头不会误命中。
- **built 的 powered 仅门控 effect_flag**：anchor_block/anchor_workshop 的推进 flag 不受 powered 影响（任务书明示 powered 只作用于 stabilizer_pylon/echo_chamber 的 effect_flag）。
- **世界回应与 Boss 倍率的落地**：`world_response_ops`/`boss_hp_multiplier`/`ending_ready` 为纯函数，本包不接线场景；`world_response_ops` 返回 `{"op": "set_flag", ...}` 形状的任务书原样字典（与 EventRunner deferred_ops 同风格，由集成层转换为 StatePatch 调用）；`boss_hp_multiplier` 供 WP13 battle 场景的 `content.hp_multiplier` 透传点使用（WP13 已留位）。
- **deferred_to_patch 的钳制时机**：桥接函数原样转发 value，0..100 钳制由 GameState 提交时统一执行（测试覆盖 120 → 100）；非字典条目跳过（与 EventRunner 的防御风格一致）。
- **允许路径遵守情况**：仅新增 `src/progression/progression.gd`（+.uid）、`tests/unit/test_progression.gd`（+.uid）与本文档；未触碰 `project.godot`、`src/narrative/`、`src/state/` 或其他包文件。
