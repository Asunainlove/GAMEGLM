# W003-A2 分支回应台词（缺口报告 B3）证据

## 目标

补上"选择后无角色回应"缺口：line 步骤获得可选条件字段 `requires_flag` /
`requires_flag_absent`，既有 5 个事件在分支选择后给出即时回应台词，使
Progression.world_response_ops 产生的 world_response flags
（world_response_exploited / boss_condition_escalated / diplomatic_stance）
与各选项 flag 拥有台词层消费者。

## 过滤点决策（最小侵入）

读现有实现后选择 **展示层过滤**：

- `EventRunner.next_step`（静态、无状态、按索引原样返回步骤）保持既有游标
  语义不变——GameSession._pump_event_step 自行维护 `_active_step_index`
  并自增，若在 next_step 内跳行会造成索引错位/重复展示，且 GameSession
  （src/integration/**）属禁改路径。
- 新增纯函数 `EventRunner.line_is_visible(step, state)`：
  - `requires_flag`：仅当 `state.flags[flag] == true` 可见；
  - `requires_flag_absent`：仅当该 flag 未置（false/缺失）可见；
  - 双字段并存取交集；无字段行恒可见；缺失键按空值处理（与
    available_events 旗标口径一致）。
- `DialogueBox.show_lines` 在展示前按 `line_is_visible` 过滤隐藏行（隐藏行
  不占展示位，行游标与事件步游标语义不变；整批隐藏时 show_lines 走既有
  空批路径同步 emit finished → 事件继续推进，不卡死）。
- `DialogueBox.snapshot_provider: Callable` 沿用 Hud/World 已有的快照注入
  模式：缺省回退 `GameState.snapshot`（生产路径 GameSession store=null →
  快照即 autoload；测试可注入独立实例）。
- schema（event.schema.json line 分支）与 ContentDB step 校验接受新字段
  （稳定 ID 校验，`_optional_stable_id`）。向后兼容：缺省无条件。
