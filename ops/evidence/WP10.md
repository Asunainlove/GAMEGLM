- `submit_action(battle, unit_key, action_id, target_key)`：校验（未 finished → `battle_finished`；单位存在 → `unknown_unit`；active 匹配 → `not_active_unit`；ally 行动合法性与目标 targeting → `unknown_action`/`invalid_target`；cost 可支付 → `insufficient_cost`），非法返回副本并追加 `{"type":"error","code":...}` 且不消耗回合；合法则结算当前 active 一人后自动推进：跳过阵亡单位，active 为 enemy 时确定性 AI 接管并连续结算，直到轮到 ally 或战斗结束。

- `outcome`：聚合阵亡敌人 drops（按 item_id 升序求和）；未结束 result `""`。

## 决策与限制

**确定性 AI 规则**（任务要求记录）：

- 行动选择：`action_ids` 声明序取**第一个 cost 可支付**的行动；全部不可支付回退第一个（回退仍不可支付 → log `action_skipped`，本回合无效果、不扣资源）。可用性只看 cost 可支付性（目标可行性在中局必然成立）。
- 目标选择：`single_enemy`/`single_ally` → 己方视角对侧/同侧**活着且 HP 最低**者，平局取 order 靠前（严格小于保持先见者）；`self` → 自身；`all_enemies` → 全体活敌方（按 order 序施加）。
- **AI 与 seed 无关**：确定性来自上述固定规则而非随机数；`seed` 仅用于 `battle_id` 命名并存入状态。测试锁定跨 seed log/outcome 一致。

**失稳恢复时机**（任务要求记录）：

- 失稳单位在其**自身下个行动回合开始时**恢复（stability=stability_max、destabilized=false）并跳过该回合行动——即任务书"跳过其下个行动回合，该回合开始时恢复"的逐字实现。恢复前的受击享受 ×1.5（如 sequence A：misa r1 脉冲失稳虫群 → luoxian r2 打击 15）。
- **守卫清零时机**：单位自身**下次行动开始**时清零（结算开始先清零、guard 行动随后重设）——按规格逐字实现，因此守卫跨回合边界持续（1v1 慢速序列 10/5/10 锁定）。
- 任务书推进一段的"越界 → turn+1、重建 order、恢复守卫/失稳"裁定为：回合边界只做 turn 递增 + order 重建（剔除阵亡）+ `round_start` log；守卫/失稳**不在边界重置**，而是按上述各自时机在单位回合开始时处理。理由：与"持续到其下次行动开始清零""该回合开始时恢复"两句逐字规格一致，且边界重置守卫会使守卫无法保护跨回合受击、边界恢复失稳会与"跳过其下个行动回合"矛盾。

**其他裁定**：

- 已失稳单位再次受到 stability_damage：无效果（stability 保持 0、不延长跳过窗口）；阵亡目标跳过一切效果（先结算伤害可击杀，后续 stability/heal 跳过）。
- 伤害取整：`floor(power × (1-guard) × 1.5)`，钳制 ≥ 0；hp 钳制 0（击杀以 `remaining <= 0` 判定）；log 的 `amount` 记生效伤害（击杀超额不显示）。
- Boss 相位采用"迁移点"形状：单位基础 `action_ids` 为初始相位，`phases[]` 为切换点（夹具 `leviathan_p2` @ 0.5）。结算后检查**所有**带 phases 的活单位，切换到满足 `hp/max_hp <= at_hp_ratio` 的最深相位；`phase_index` 单调锁存（只切一次、只记一次 `phase_change`）。若 WP12 数据采用"完整相位表"形状（含 ratio 1.0 的首相位），首次结算后会多一次冗余 `phase_change`（行为正确但日志冗余）——集成时按迁移点形状供数即可。
- 敌人回合触发方式：active 为 enemy 时，调用方以 `submit_action(battle, <enemy key>, "", "")` 触发，传入 action/target 被忽略、由 AI 决策（任务书"active 是 enemy → 确定性 AI"语义）；ally 行动合法性校验只对 ally 生效。
- ally 资源不足按非法行动处理（`insufficient_cost`，不耗回合、零修改），与敌方 AI"跳过继续"不同——玩家输入路径应显式失败而非静默浪费回合。
- items 计数归零即删除键（保持状态字典干净）；守卫/失稳同时作用于同一目标时伤害 ×(1-guard)×1.5 连乘后取整。
- 胜负检查先 victory 后 defeat（行动者必存活于己方，同时归零不可达）；`all_enemies` 在无活敌方时记 action 空 targets、无效果（边界防御）。
- **增补字段**（任务书字段清单之外的附加输出，消费方应以 `get` 容错）：battle 增 `result`（"victory"/"defeat"/""）与 `action_defs`（submit 自足解析所需）；unit 增 `kind`、`name_zh`（表现层免二次查表）、`drops`（任务书推荐：create 时拷进单位）、`phase_index`。log 为结构化条目（`action`/`damage`/`defeated`/`destabilized`/`destabilized_recover`/`turn_skipped`/`heal`/`guard`/`item_used`/`action_skipped`/`phase_change`/`round_start`/`battle_end`/`error`），表现层可过滤整形。
- 行动 `kind` 字段不驱动效果（power/stability_damage/heal/guard_ratio/cost 字段驱动），仅透传给表现层；无多段伤害/追击/反伤等机制（切片范围外）。
- 引擎不依赖 ContentDB：unit_defs/action_defs 经 config 注入，WP13 `EncounterDirector.start` 组装 config、WP12 供数即可；schema 校验归 WP01/离线门禁，引擎对非法定义取安全缺省（max_hp/stability_max/speed 钳制 ≥ 1）。
