## 实现

**任务 1（多 chunk 渲染 + 全量 delta 同步）**
- `world_renderer.gd`：`render(chunk, chunk_origin := Vector2i.ZERO)`（缺省参数
  保持既有 1 参调用方/测试兼容）按 origin 平移写入两层；**render 不再清层**，
  新增 `clear_layers()` 供全量重绘；新增 chunk 感知 `apply_delta(chunk_id,
  cell, destroyed)`（内部经 `ChunkData.chunk_origin` 换算 origin；destroyed=false
  为文档化 no-op）；保留 `apply_deltas(Array[Vector2i])` 旧形态（世界绝对坐标，
  chunk_0_0 兼容缝）。
- `chunk_data.gd`：新增 `grid_coords(chunk_id)`（解析 `chunk_<x>_<y>`，不匹配
  返回 (-1,-1)）与 `chunk_origin(chunk_id)`（grid × CHUNK_SIZE，解析失败降级
  (0,0)）。
- `world.gd`：`_render_all_chunks()` 渲染全部 8 chunk（origin =
  `Vector2i(grid_x, grid_y) * CHUNK_SIZE`）；`refresh_from_snapshot()` 重读
  `snapshot.chunk_deltas` **全量**按 chunk 分发（未知 chunk 跳过）；轮询逻辑
  不变。**坐标修复**：`cell_def_at` 现把世界格减 origin 转本地再查——同时修复
  非 chunk_0_0 的采集地形解析与建造地形校验。
- `scenes/world.tscn`：4 面 StaticBody2D 边界墙（厚 64px，覆盖 4096×2048 外沿
  含四角；左右墙 shape 64×2176，上下墙 4224×64），玩家默认 collision mask
  即可被阻挡。

**任务 2（相机）**
- `scenes/world.tscn`：`Camera2D`（`position_smoothing_enabled`，limit_left/top
  =0、right=4096、bottom=2048，zoom 默认 1.0，初始位 (64,64)）。
- `world.gd`：`_spawn_player` 成功后 `_attach_camera` 将场景相机 reparent 为
  player 子节点并 snap 到 (0,0)（读档位置也立即居中）；player 缺席时相机留在
  world 根。headless 冒烟由 `test_camera_exists_with_world_limits_and_follows_
  player` 覆盖（存在性 + 4 limit + smoothing + 成为 player 子节点）。

**任务 3（位置持久化）**
- `game_session.gd`：新增注入点 `player_cell_provider: Callable`（缺省从绑定
  player 节点 position/32 取格）；`_checkpoint_player_position(reason)` 经
  `begin_patch`（source_id `integration_player_position_<reason>_<revision>`，
  expected_revision = snapshot.revision）+ `patch.set_player_position` 落账；
  检查点接入：**战斗开始**（`_start_encounter`）、**战斗结束**
  （`_on_encounter_finished`）、**每次事件完成后**（`_finish_active_event`）、
  **存档前**（`save_now` 与 `_on_save_requested`；auto 节流不变）。
- 读档复位：`_try_load_autosave` 成功 restore 后调
  `_place_player_from_saved_snapshot` → `world.place_player_at_cell(cell)`；
  world 侧 `_spawn_player` 亦支持 `player_start_cell` 注入 / 直接读
  `snapshot.player.position`；**默认 (0,0) 视为未持久化**，保留 PlayerSpawn

## 决策与限制

1. **delta 坐标语义（关键决策）**：任务书要求 `apply_deltas` 接受带 chunk_id
   的 delta 并"内部换算 origin"。实测持久层（`Gathering.apply_mining`）按
   **app 层传入的世界格坐标**原样存 delta（save_version 1 冻结 schema，
   `SaveCodec` 对坐标无 0..31 界检查）。因此换算缝放在 world.gd：世界绝对
   delta − origin → 传 chunk 本地格给 `apply_delta`，渲染器 + origin 还原——
   端到端净恒等、擦除位置正确，渲染器 API 保持 chunk 本地语义（与
   `render(chunk, origin)` 对称），且未来若迁移为本地 delta 只需删 world 侧
   一次换算。改存本地坐标需 save schema 版本升级，超出本包允许路径。
2. **相机跟随方案**取任务书"最简"分支（player.add_child），未做 sibling+clamp
   跟随；position_smoothing 保留。
3. **边界墙**为结构断言（4 StaticBody2D + RectangleShape2D + 位置外沿检查）；
   未写物理模拟推挤测试（headless 物理回归成本高、收益低，墙几何由常量推导
   并被位置断言锁定）。
4. **位置检查点频度**：每次 autosave（采集耗尽/建造后节流 2s）都会因"存档前"
   检查点多提交一个 position patch（revision +1）。幂等 source_id + 节流使
   开销可控；若未来要合并进业务 patch，需要扩 StatePatch 组合语义（state 层
   禁改，故不在本包）。
5. **测试替身保活**：test_world_gap3 的 SnapshotStore 必须存实例字段——
   `Callable` 只持 ObjectID，临时 RefCounted 被释放后 provider 失效，world 会
   静默回退 GameState autoload（调试期以探针定位，探针已删）。已在测试文件
   注释中记录。
6. `test_loaded_snapshot_places_player_at_saved_cell` 复用共享 world 实例：
   fresh session 读档后移动的是同一 player 节点（与生产 app.tscn 单 world 一致）。
